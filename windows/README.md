# Windows SNMP monitoring demo

NetXMS 7.0.4, its web console, and the Windows SNMP service run natively on one Windows 11 x64 PC. NetXMS polls SNMPv2c every 10 seconds and stores samples and alarms in a local SQLite database. No virtual machine is needed; an existing VirtualBox host-only adapter or spare USB Ethernet adapter can be used as the secondary link.

## Set up

1. On a clean demo PC, download the [NetXMS server](https://netxms.org/download/releases/7.0/netxms-server-7.0.4-x64.exe) and [web console](https://netxms.org/download/releases/7.0/netxms-webui-7.0.4-x64.exe) installers to the same folder. The setup script checks their Windows signatures. Do not run it over an existing NetXMS or configured SNMP installation.
2. In Windows PowerShell as administrator, from `windows/`, run:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Install-Demo.ps1 -InstallerDirectory "$env:USERPROFILE\Downloads"
   ```

   Installing the Windows SNMP optional feature requires access to Windows Update or your organization's feature source. If Windows requests a restart, restart and rerun the installer. Run all steps under the same Windows account: the locally generated login and SNMP community are encrypted for that account.
3. With both links up, use `Get-NetAdapter` to find their names. Configure the dashboard with the actual main link and an unused secondary adapter. For example:

   ```powershell
   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Configure-Demo.ps1 -MainAdapter 'Wi-Fi' -DemoAdapter 'Ethernet 2'
   ```

   The script reads the current adapter indices and checks for live SNMP responses. Rerun it if adapter names, indices, or the main link change. The web console can take a few minutes to start.

## Run the demo

Double-click `Run-Demo.cmd`. Sign in to [the local console](http://127.0.0.1:4788/nxmc/) using the displayed credentials and open **Dashboards → Windows SNMP Interface Demo**. Return to the launcher, press Enter, and approve UAC. The test disables only the designated demo adapter, waits for SNMP and the threshold alarm, then re-enables it and checks recovery. It refuses to toggle an adapter with a default route or active TCP connections, and schedules a restore in case it is interrupted.

The packaged launcher was verified on an existing Windows install with Wi-Fi as the main link and `Ethernet 2` as the secondary adapter:

| Phase | Secondary `ifOperStatus` | Main link | Demo SNMP alarm |
| --- | --- | --- | --- |
| Baseline | `1` (up) | Up | Inactive |
| Secondary disabled | `2` (down) | Up | Outstanding |
| Recovered | `1` (up) | Up | Cleared |

Credentials, generated config, and `test-results.json` stay in `%LOCALAPPDATA%\NetXMS-SNMP-Demo`, outside the clone. Keep the launcher password and that directory private. If interrupted, leave the scheduled restore in place or manually re-enable the demo adapter in Windows before running again. Do not disable the main link.

## Monitoring notes

- `sysUpTime.0` (`1.3.6.1.2.1.1.3.0`) is the SNMP reachability check. Interface status is `ifOperStatus.<ifIndex>` (`1.3.6.1.2.1.2.2.1.8.<ifIndex>`).
- SNMP access is read-only and restricted to `127.0.0.1`. SNMPv2c is not encrypted; do not expose this setup on the network. The NetXMS metrics explicitly use port `161` because loopback is excluded from automatic SNMP capability discovery in this release.
- The threshold events are generated by polling, not traps. The chart and indicators also have their own refresh timing. A monitor running on this PC cannot report that the entire PC has powered off in real time.
